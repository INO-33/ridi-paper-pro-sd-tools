# 백업으로 롤백 (실기기 시험 전)

이 도구로 만든 `e70q10-backups/CID/작업ID` 전체 스냅샷을 같은 기기에 복원합니다.
구형 9월 원본 백업처럼 다른 파일 형식은 지원하지 않습니다.

## 사용

1. 백업이 들어 있는 FAT32 SD를 PC에 연결합니다. PC에 보관한 백업이면
   전체 작업 폴더를 SD의 원래 `e70q10-backups/CID/작업ID` 위치로 먼저 복사하세요.
   이 GUI는 백업을 다른 SD로 자동 복사하지 않습니다.
2. GUI의 **백업으로 롤백**을 선택합니다. 백업 생성은 업그레이드/업데이트의
   체크 옵션이며, 롤백은 별도의 복원 작업입니다.
3. `device.txt`, `SHA256SUMS`, `complete`, `emmc.partXX`, `boot0.bin`,
   `boot1.bin`이 있는 작업ID 폴더와 해당 SD를 선택합니다.
4. SD 준비를 누릅니다. PC에서 백업 전체를 검증하고 삭제 범위 확인을 거칩니다.
   SD 포맷은 사용할 수 없습니다. 백업 폴더는 유지합니다.
5. SD를 기기에 삽입하고 fastboot 진입 후 GUI의 RAM 부팅 버튼을 누릅니다.
6. RAM에서 기기와 백업을 다시 확인한 뒤 복원합니다. 성공 시 재부팅하고,
   SD를 PC로 옮겨 **SD 결과 확인**으로 결과를 확인합니다.

**현재 OS, 앱, 책, 설정과 사용자 데이터는 모두 백업 시점으로 덮어씁니다.**
롤백 직전 상태는 자동 백업하지 않습니다. 필요한 현재 데이터는 별도로 보관하세요.
원본 백업에는 개인정보가 포함됩니다. 커뮤니티 배포본에 개인 백업을 포함하지 마세요.

## 기록과 보호 범위

- 같은 eMMC CID와 용량만 허용합니다. 타 기기 복제 용도로 사용하지 않습니다.
- 완료 마커, 파일 목록/크기/체크섬, 메타데이터를 검증합니다.
- PC 검증 후에도 RAM에서 모든 백업 파일을 다시 해시 검사합니다.
  어느 하나 실패하면 내부 eMMC 기록을 시작하지 않습니다.
- 보호 구간인 섹터1~104447(부트로더·기기 자료·recovery 포함) 및 boot0/boot1은
  현재 내용과 백업이 일치해야 합니다. 이 영역은 쓰지 않습니다.
  다르면 별도의 펌웨어 복구가 필요한 상황으로 중단합니다.
- 51MiB부터 eMMC 끝까지 복원하고 조각별로 독립 읽기 해시를 확인합니다.
- 모든 데이터 검증이 끝난 뒤 원본 MBR 섹터0을 마지막에 기록·검증합니다.
  성공 시 전체 user area는 스냅샷과 바이트 단위로 일치하고 boot0/boot1도 일치합니다.
- 성공한 작업을 같은 RAM 이미지로 다시 부팅하면 반복 기록하지 않습니다.
- 실패 시 자동 재부팅하지 않습니다. 로그는 `e70q10-update-status/last.log`,
  결과는 `last.result`에 기록합니다. 실패한 같은 RAM 세션의 재실행은 차단합니다.

전원 단절이나 기록 도중 오류가 나면 일부만 복원된 상태가 될 수 있습니다.
자동으로 원자적 롤백되는 기능은 아닙니다. 중단 시 정상 OS로 부팅하지 말고
로그를 확인한 뒤 RAM을 새로 부팅해 같은 전체 복원을 재시도해야 합니다.

## 검증 범위

Linux에서 실제 복원 셸과 네이티브 읽기/쓰기 도구를 임시 일반 파일로 실행했습니다.
두 백업 조각의 경계와 마지막 부분, 전체 바이트 일치, MBR 마지막 기록,
완료 재실행 방지, 다른 CID/용량, 백업 손상, firmware/boot 차이,
쓰기 실패, 읽기 검증 실패, 설정 불일치를 확인했습니다.
Tk GUI에서 롤백 선택 시 SD 포맷과 백업 체크가 비활성화되는 것도 확인했습니다.
큰 임시 파일은 시험 종료 시 삭제합니다.

**실제 기기 복원, 전원 단절 복구, Windows 네이티브 실행은 아직 미검증입니다.**
배포 시 이 기능을 실험적 기능으로 표시하세요.
